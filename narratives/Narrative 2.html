Ricky Suarez CS 499 Milestone Three Enhancement Two Narrative: Algorithms and Data Structures Artifact Description The artifact I selected is the Grazioso Salvare Rescue Dog Dashboard, which I originally created during my CS 340 course before beginning CS 499. The dashboard is a Python application that uses Dash, pandas, Plotly, Dash Leaflet, and MongoDB to help Grazioso Salvare review animal shelter records. Users can view animal information in a table, filter records by rescue category, display the location of a selected animal on a map, and review outcome information through a bar chart. The dashboard also uses a separate Python CRUD module to connect to the MongoDB animal collection. Justification for Including the Artifact I included this artifact in my ePortfolio because it demonstrates how algorithms and data structures can improve an application that already performs a useful organizational function. The original dashboard filtered animals using MongoDB queries, but it did not compare candidates or identify which animals were the strongest choices for rescue training. Every matching animal was treated equally. This limited the dashboard because a rescue organization would still need to manually review the records to decide which animals appeared most suitable. For this enhancement, I added a scoring system that evaluates each dog according to breed, sex, age, available coordinates, and whether the animal has a known name. The scoring requirements for water rescue, wilderness rescue, and disaster or tracking were stored in dictionaries. This allows the same scoring function to process multiple rescue categories instead of requiring a separate algorithm for each one. Breed matching is worth 40 points, sex matching is worth 25 points, age matching is worth 25 points, valid coordinates are worth 5 points, and a known name is worth 5 points. This produces a maximum candidate score of 100. The most important algorithmic improvement was the use of Python’s heapq module to maintain a minimum heap containing the top 10 rescue candidates. The algorithm evaluates each dog and compares its score with the lowest scoring candidate currently stored in the heap. Once the heap contains 10 candidates, a new animal is added only when it has a better score than the lowest ranked candidate. This approach has an expected time complexity of O(N log K), where N is the number of animals evaluated and K is the number of candidates retained. A full sorting approach would require approximately O(N log N) time. Keeping K limited to 10 allows the application to identify the strongest candidates without sorting every dog in the collection. I also added rank and candidate score fields to the dashboard table so users can understand why one dog appears above another. A small cache stores recently calculated results for 60 seconds. This prevents the dashboard from repeating the same database read and ranking process every time the same filter is selected within a short period. Together, the dictionaries, heap, tuples, lists, and cache demonstrate my ability to select data structures based on the needs of the application. Reflection on the Enhancement Process The most important lesson I learned from this enhancement was that choosing the correct data structure depends on how the results will be used. My first thought could have been to score every animal and sort the entire list. That approach would have worked, but it would perform unnecessary work because the dashboard only needs the top candidates. Using a heap showed me how an algorithm can produce the same useful result while maintaining only a small portion of the data during processing. I also learned that an algorithm is only as useful as the criteria used to evaluate the data. The scoring matrix required me to decide how much importance to assign to breed, age, sex, location information, and the animal’s name. Breed received the highest value because the rescue categories are strongly connected to preferred breeds. Age and sex were also important because they were part of the original rescue requirements. Coordinates and names received smaller values because they improve the usefulness of the candidate record but do not directly determine rescue suitability. This process helped me understand that algorithm design often includes judgment and tradeoffs rather than only writing code. One challenge was making sure that animals with the same score could still be stored safely in the heap. Python may attempt to compare the next item in a tuple when two scores are equal. Because MongoDB records are dictionaries and dictionaries cannot be ordered against each other, I used the record number as a tie breaker. This allowed the heap to compare entries without attempting to compare the animal dictionaries directly. Another challenge was adding the enhancement without changing the working dashboard more than necessary. I wanted to preserve the radio filters, table, map, chart, and MongoDB connection from the previous milestone. I added the algorithm functions and changed only the table update process needed to display ranked candidates. Testing confirmed that selecting a rescue category now displays the top 10 candidates, while Reset still displays the complete collection.
