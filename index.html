Enhancement Two: Algorithms and Data Structures

Rescue Candidate Ranking System

The second enhancement changed the dashboard from a basic filtering application into a decision support system. Instead of treating every matching dog equally, the dashboard evaluates available animals and ranks the strongest candidates for each rescue role.

Candidate Scoring

Each animal receives a score based on rescue qualifications including breed, sex, age, valid location information, and whether the animal has a known name. The highest possible candidate score is 100.

Heap Based Selection

Python's heapq data structure is used to maintain only the top 10 rescue candidates while records are processed. Instead of sorting the entire collection, the algorithm maintains a minimum heap containing only the strongest candidates.

This provides approximately O(N log K) processing, where N represents the number of animals evaluated and K represents the number of candidates retained.

A short term cache is also used to avoid repeating the same ranking operation when a filter is selected multiple times within a short period.

Enhancement Three: Databases

MongoDB Database Enhancement

The third enhancement focused on improving how the Grazioso Salvare application retrieves, processes, monitors, and protects information stored in MongoDB.

Database Improvements

  • Added compound MongoDB indexes supporting commonly queried rescue candidate fields.
  • Added an index for animal ID lookups.
  • Added MongoDB aggregation pipelines for calculating animal outcome totals.
  • Moved outcome reporting from pandas processing into MongoDB.
  • Added an administrative audit collection that records database create, update, and delete activity.
  • Continued using authenticated database access and environment based credential management.

These changes demonstrate how database design can improve performance, accountability, security, and the usefulness of information provided to an application.
